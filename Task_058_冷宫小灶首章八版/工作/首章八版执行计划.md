# 《九十二天后我会死，幸好我的菜会说话》首章八版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 依据已确认的设定与结构规则，完成八个切入点不同、可独立发布测试的第一章版本，并交付一份便于横向筛选的 Markdown 成稿。

**Architecture:** 先固化来源材料与共同检查表，再按两版一批完成草稿，最后进行跨版本去同质化审查和逐版硬指标验收。八版共享事实合同，但开场场景、信息顺序、冲突动作、笑点和章尾表达分别设计。

**Tech Stack:** 中文 Markdown、PowerShell 只读统计、人工叙事审查与逐版验收表。

## Global Constraints

- 结构规则以《古言写作规则 v1》为最高优先级，故事事实以主设定包为准。
- 每版 1800—2000 字，且不得超过 2000 字。
- 每版必须完成身份、金手指、92 天死亡倒计时。
- 每版至少一次正面冲突并当场出结果，至少两处自然笑点。
- 每版章尾必须提供新信息，不以泛化危机感收尾。
- 有名字的出场人物最多三人，限定为苏合、小满、冯全。
- 金手指必须遵守触发方式、单句输出、用心程度和同人同日一次四条限制。
- 八版不复制参考作品的句子、桥段组合或人物关系。
- 工作材料与检查记录放入 `工作`，最终成稿只放入 `产出`。
